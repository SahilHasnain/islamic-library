# Android CI

Generated by android-ci init.

## Build choices

- **debug-apk**: creates an installable debug APK and uploads it as a GitHub artifact (uses development package ID suffix .dev).
- **preview**: creates an installable preview APK and uploads it as a GitHub artifact (uses preview package ID suffix .preview, no expo-dev-client bundled).
- **production**: signs an Android App Bundle, uploads it as an artifact, and deploys it to Google Play.
- Pushes to main and pull requests run the debug APK build. Production and preview must be selected manually.

## Expo prebuild layout

The workflow generates android/ with Expo prebuild on the GitHub runner. Keep that generated native directory out of Git. Fastlane is kept in the repository root so it survives prebuild:

- Gemfile
- fastlane/Fastfile
- scripts/patch-android-release-signing.mjs

## GitHub Actions secrets

- ANDROID_KEYSTORE_BASE64
- ANDROID_KEYSTORE_PASSWORD
- ANDROID_KEY_ALIAS
- ANDROID_KEY_PASSWORD
- PLAY_STORE_JSON_BASE64
- GOOGLE_SERVICES_JSON_BASE64 when app.json configures android.googleServicesFile.

Set the secrets in the repository's **Settings → Secrets and variables → Actions**.

The workflow defaults to the production Play track. Set the repository variable PLAY_TRACK to change it. The service account must have access to the Play Console app for com.islamiclib.

## Run it

Open **Actions → Android CI → Run workflow** and choose **debug-apk**, **preview**, or **production**.
